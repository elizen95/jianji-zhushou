# 贯穿全片的 Three.js 与 Blender 制作

## 拆文案与选型

从原句列出观众要看懂的对象、相对位置、动作、因果和结果。为开场、章节、主体段和收束逐段评估三维表达，按叙事需求广泛采用。场景标注句 ID、镜头 ID、母版入出帧、叙事动作、拟用工具、选型理由与资产。档案、原始视频和严谨地图继续按各自规则展示；可在相邻镜用三维解释其关系。

优先在本地 86 库（含 #87、#88）、Claude Motion、Video Talkcraft、地图及其他合适的插件／模板库中找实际片段或源码。记录案例、路径或时间点，以及本镜借鉴的相机、物件关系、分层、光材质或动作。将实际选用的模板、组件或写法落到工程，统一全片视觉风格。让物件有体积、运动有空间路径、前后有遮挡，配合克制的景深与光影。可用物件交接、剖切、景别切换、前后关系转换、场景状态变化等方式呈现因果，避免在多镜反复用一条线移动表达所有机制。

建模时查 WiseWong6/wise-motion 的本地 SKILL.md 和 catalog，按镜头选择可参考的体块、比例、部件与材质；记录实际案例。用 Three.js 或 Blender 实现，并按史料核对造型。

## 缺少视觉参考

先区分缺艺术参考和缺事实依据。有文案依据时，从对象关系、比例范围、材质、光向与动作设计原创三维原型。用基础体块与机位明确剪影、尺度、层次和动作结果，再扩成正式工程。历史题材优先查原始史料、馆藏或可靠图集；将能证实的细节、合理推断和概念表达登记在镜头台账。缺证据的军阵、建筑、器物、地貌或路线用概念示意或省略细节，遵守地图真实数据与路线规则。

## 实现与合成

| 工具 | 适用场景和实现要求 |
|---|---|
| Three.js | 实时可调的分层地形、器物拆解、物件运动、实例化群组、空间标签与连续运镜。Remotion 或渲染宿主传入母版帧、fps 和镜头偏移；动画由时间与固定随机种子决定，支持任意帧跳转和重复渲染。登记相机、灯光、模型、纹理及依赖锁。 |
| Blender | 复杂几何、雕刻细节、真实材质、灯光、粒子或烟尘、章节标志和电影感镜头。用 .blend 或可重建场景的 Python 交接，并提供实际用到的脚本、贴图与链接资产。记录相机、场景、渲染器、CPU／GPU 方案、帧范围、采样及输出目录。 |
| 混合 | Blender 模型需要实时合成时可用 GLB／glTF，交接注明单位、轴向、原点、贴图、材质与动画限制；需要离线光效时输出透明图像序列或背景片并在母版合成。统一画幅、fps、首帧、帧编号、色彩与 Alpha，保留字幕安全区。 |

开场用动作结果或证据直接入题；2 秒章节卡给完整画面、可读标题和本章物件或材质运动；正文用变化中的空间关系与状态推进；收束用新视点或新关系回扣文案。可共享物件、灯光和色彩系统，同一成镜或动效离屏至少 300 秒；同义解释离屏至少 120 秒，同时触发时取较长窗口。单个[章卡标志动画](motion-variety.md)按专属例外执行。镜头原则、图像调度与参考组件同步记录。

## 渲染交接与集中审阅

代码阶段先交可运行工程、资产、依赖版本、入口、帧范围、母版同步方式、预设及准确命令。按制作机提供快速技术预设与正式输出预设，列清本机验证、后续批量渲染和预期输出路径。未执行的场景或渲染如实标明。技术验证优先用依赖／资源检查、类型与构建、帧范围、解码和运动数据；定位具体异常时做必要的定点检查。

按镜头和文字时码一次选取应审构图及有意义的动作阶段，与全片其他画面一并交到同一份 PDF 和同页 ID 的 Word。未批量渲染时标明布局、已渲染代表帧和待渲染范围。回修沿用镜头、页和文字 ID，只更新影响的三维资产、帧段及对应审阅页。
